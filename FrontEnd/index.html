Aula 15

Prettier, ESLint e Babel

Baixar aula15.docx
01

Como o Prettier e o ESLint contribuem para a consistência e a qualidade do código?

Os dois cumprem papéis diferentes e complementares. O Prettier é um formatador: ele reescreve automaticamente indentação, aspas, ponto e vírgula e quebras de linha seguindo um padrão único, então dois desenvolvedores diferentes produzem código visualmente idêntico, o que elimina discussões de estilo em revisão de código.

O ESLint é um analisador estático (linter): ele lê o código sem executá-lo e aponta problemas reais, como variáveis não usadas, comparações perigosas, importações quebradas ou más práticas da equipe. Enquanto o Prettier cuida da forma, o ESLint cuida do conteúdo. Usados juntos, reduzem bugs antes mesmo de rodar o programa e mantêm uma base de código consistente entre todos os membros de um time.

02

Por que Babel é importante ao desenvolver para diferentes navegadores?

Navegadores mais antigos não entendem todos os recursos do JavaScript moderno (ES6+), como arrow functions, let/const, classes ou desestruturação. O Babel transpila esse código moderno, convertendo-o para uma versão equivalente em uma sintaxe mais antiga (geralmente próxima do ES5), que praticamente qualquer navegador consegue interpretar.

Isso permite que a equipe escreva com a sintaxe mais atual e produtiva, sem abrir mão de compatibilidade com navegadores e dispositivos mais antigos que os usuários da aplicação ainda possam usar.

03

O que você observou de diferenças entre o código original e o código transpilado por Babel?

Ao comparar os dois arquivos, normalmente aparecem trocas como: let/const viram var; arrow functions viram function tradicionais; template literals (com crase) viram concatenação de strings com +; desestruturação é expandida em atribuições separadas; e classes ES6 são convertidas em funções construtoras com métodos no prototype.

O comportamento final é o mesmo, mas o código transpilado costuma ficar mais longo e menos legível — é o preço da compatibilidade com navegadores mais antigos.

Aula 16

Animações em páginas web

Baixar aula16.docx
01

Como a adição de animações melhora a experiência de usuário em uma página web?

Animações dão feedback visual imediato sobre o que está acontecendo: um botão que reage ao clique, um menu que desliza para abrir, um item que se destaca ao passar o mouse. Isso ajuda o usuário a entender o que é interativo e o que mudou de estado na tela.

Elas também tornam as transições entre estados menos abruptas — em vez de um elemento simplesmente sumir e outro aparecer, uma transição suave guia o olhar do usuário e evita que ele se perca no contexto. No conjunto, isso aumenta a percepção de qualidade e profissionalismo da interface.

02

O que pode acontecer com o desempenho da página ao se adicionar várias animações? Quais práticas você aplicaria para minimizar o impacto?

Muitas animações rodando ao mesmo tempo podem sobrecarregar a renderização, causando quedas de quadros por segundo (jank), travamentos visuais e maior consumo de bateria e CPU, especialmente em celulares mais simples.

Para minimizar o impacto: priorizar animações em propriedades leves para o navegador, como transform e opacity, em vez de propriedades que forçam recálculo de layout, como width, top ou left; evitar animar muitos elementos ao mesmo tempo; usar will-change com moderação; e respeitar a preferência do usuário por menos movimento com a media query prefers-reduced-motion.

03

Qual é a diferença prática entre usar animações CSS e JavaScript? Em que situações você escolheria uma abordagem em vez da outra?

Animações em CSS (transition e @keyframes) são declarativas: o navegador cuida da execução, geralmente de forma mais performática, e o código é simples de escrever e manter. Em troca, o controle é limitado — não é fácil pausar, reverter ou reagir a lógica complexa em tempo real.

Animações em JavaScript (Web Animations API ou bibliotecas) dão controle total: dá para iniciar, pausar, reverter, encadear ou basear a animação em dados dinâmicos e eventos do usuário. Em geral, CSS é a escolha para animações simples e previsíveis, como estados de hover e transições de interface; JavaScript entra quando a animação depende de interação complexa ou de dados que mudam em tempo de execução.

Aula 17

fetch, axios e consumo de APIs

Baixar aula17.docx
01

Qual é a diferença entre fetch e axios para realizar requisições HTTP em JavaScript?

fetch é uma API nativa do navegador — não precisa instalar nada — mas exige mais código manual: é preciso chamar .json() para converter a resposta, e ela só rejeita a Promise em falha de rede, não quando o servidor responde com erro (como 404 ou 500).

axios é uma biblioteca externa (instalada via npm) que já converte a resposta em JSON automaticamente, rejeita a Promise sozinha em respostas de erro, permite configurar timeout, cancelar requisições e usar interceptors para tratar toda requisição de forma centralizada. Em resumo: fetch é mais simples de disponibilizar, axios é mais completo e conveniente para projetos maiores.

02

Por que é importante tratar erros ao realizar requisições para uma API? Como isso pode ser feito no código?

Uma requisição pode falhar por vários motivos fora do controle do código: conexão instável, servidor fora do ar, chave de API inválida ou limite de uso excedido. Sem tratamento de erro, a aplicação pode travar, exibir tela em branco ou mostrar dados incorretos para o usuário, sem explicação do que houve.

No código, isso é feito com try/catch ao usar async/await (ou .catch() com Promises), verificando também se response.ok é verdadeiro antes de processar os dados no caso do fetch. É boa prática exibir uma mensagem clara ao usuário e registrar o erro para facilitar a depuração.

03

O que significa o parâmetro units=metric na URL da API OpenWeatherMap e qual é a sua importância?

Esse parâmetro define o sistema de unidades da resposta da API. Por padrão, a OpenWeatherMap retorna a temperatura em Kelvin; com units=metric, ela passa a retornar em graus Celsius e a velocidade do vento em metros por segundo, unidades usadas no Brasil.

A importância prática é evitar conversões manuais no código e reduzir o risco de exibir dados em uma unidade que o usuário não reconhece — sem esse parâmetro, seria necessário converter Kelvin para Celsius manualmente antes de mostrar a temperatura na tela.
