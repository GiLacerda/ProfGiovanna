Integração com APIs externas

Aula 1 · [SIS]ANO2C1B3S18A1

Conceitos-chave

API (Application Programming Interface) é a interface que permite que uma aplicação mobile se conecte a serviços externos para consumir e enviar dados — por exemplo, autenticação, recuperação de informações ou armazenamento em nuvem.

Autenticação de API

A maioria das APIs exige autenticação para controlar quem pode fazer requisições:

TipoComo funciona
Chave de APIIdentificador único fornecido pelo serviço, enviado em cada requisição para autenticar o app.
OAuthProtocolo mais robusto, que permite acesso autorizado em nome de um usuário (sem que o app precise conhecer a senha dele).

Consumo de dados

Consiste em fazer requisições HTTP (GET, POST etc.) para endpoints específicos da API. Os dados retornados geralmente vêm em JSON (JavaScript Object Notation) ou XML — o formato de resposta influencia diretamente como o app vai tratar e exibir essa informação.

Por que isso importa: antes de consumir uma API, é preciso saber como ela autentica as requisições e em que formato ela devolve os dados — do contrário, o app não consegue interpretar corretamente a resposta nem garantir que a chamada seja aceita pelo servidor.
Situação-problema — TravelWeather A empresa TravelWeather, especializada em viagens, deseja implementar um recurso no aplicativo mobile que exibe previsões do tempo para os destinos escolhidos pelos usuários. Para isso, será necessário integrar uma API de clima fictícia chamada WeatherPlus.

Atividade prática — o que fazer

  1. Pesquisem a documentação da API fictícia "WeatherPlus" e entendam como a autenticação e os endpoints funcionariam.
  2. Planejem como obter os dados da API, considerando: quais dados precisam ser solicitados (ex.: temperatura, umidade) e qual formato de resposta será analisado (JSON ou XML).
  3. Imaginem possíveis falhas na autenticação ou nos dados recebidos e pensem em como tratar esses erros.
Dica para tratamento de erros: pense em cenários como token expirado, endpoint fora do ar, resposta em formato inesperado ou dados incompletos — e o que o app deveria exibir ao usuário em cada caso, em vez de simplesmente travar.

Utilização de serviços de back-end como serviço (BaaS)

Aula 2 · [SIS]ANO2C1B3S18A2

Conceitos-chave

BaaS (Backend as a Service) fornece funcionalidades de back-end — como armazenamento, autenticação e notificações — em um modelo de serviço pronto para uso. Isso elimina a necessidade de construir essa infraestrutura do zero, permitindo que a equipe se concentre na experiência do usuário.

ServiçoO que oferece
FirebaseAutenticação, banco de dados em tempo real e notificações — amplamente usado em apps mobile.
AWS AmplifyAPIs GraphQL e REST, armazenamento de arquivos e integração com AWS Lambda.

Casos de uso típicos: aplicativos que precisam de notificações em tempo real e gerenciamento de grandes volumes de dados em nuvem sem manter servidor próprio.

Trade-off a considerar: BaaS acelera o desenvolvimento, mas também cria dependência de um provedor externo — vale pensar em custos de escala, limites de uso gratuito e o que acontece se o serviço apresentar instabilidade.
Situação-problema — Foodly A Foodly, um aplicativo de pedidos de comida, quer implementar notificações para alertar usuários sobre promoções e confirmar pedidos. A equipe deseja usar o Firebase para essa funcionalidade.

Atividade prática — o que fazer

  1. Pesquisem como o Firebase oferece suporte para autenticação e notificações.
  2. Planejem a estrutura necessária para gerenciar usuários e enviar notificações.
  3. Identifiquem desafios que podem surgir ao usar um serviço BaaS (ex.: limites de uso, dependência do provedor, custos) e pensem em como a Foodly poderia superá-los.

Integração com serviços de mensageria

Aula 3 · [SIS]ANO2C1B3S18A3

Conceitos-chave

Serviços de mensageria — como RabbitMQ ou o Firebase Cloud Messaging (FCM) — facilitam o envio e recebimento de mensagens entre dispositivos ou sistemas. São amplamente usados em notificações push, chats e comunicação entre sistemas.

Configuração

  • Configuração inicial do serviço escolhido (ex.: criação de filas no RabbitMQ).
  • Registro de dispositivos para que possam receber notificações.

Envio e recebimento de mensagens

  • Mensagens podem ser enviadas a usuários específicos ou em massa, dependendo do contexto.
  • É importante gerenciar filas e confirmações de entrega para garantir que as mensagens realmente cheguem ao destino.
Por que gerenciar filas importa: sem uma fila bem gerenciada, mensagens podem se perder, chegar fora de ordem ou ser entregues em duplicidade quando o sistema está sob carga ou quando um dispositivo está temporariamente offline.
Situação-problema — ShopTrack O aplicativo ShopTrack deseja implementar notificações que informam o status do pedido (ex.: "Pedido enviado", "Pedido entregue"), utilizando o Firebase Cloud Messaging.

Atividade prática — o que fazer

  1. Pesquisem as etapas para configurar o Firebase Cloud Messaging.
  2. Planejem como as notificações serão enviadas e recebidas pelos dispositivos.
  3. Identifiquem como as mensagens poderiam ser categorizadas (ex.: por urgência ou tipo de evento) para melhorar a experiência do usuário.

Armazenamento de dados e repositórios: monitoramento e logs

Aula 4 · [SIS]ANO2C1B3S18A4

Ferramentas de monitoramento

Ferramentas de monitoramento são essenciais em integrações com serviços de terceiros porque permitem identificar, analisar e resolver problemas na interação entre o app e as APIs externas — coletando métricas como erros, tempos de resposta e padrões de uso.

FerramentaPara que serveBenefícios
Firebase Crashlytics Monitoramento de falhas em tempo real Relatórios detalhados (dispositivo, SO, comportamento antes do erro); integração com e-mail/Slack
Sentry Monitoramento de erros e falhas, com suporte a várias linguagens (Kotlin, Swift...) Visualização do fluxo de eventos até o erro; rastreamento de desempenho (performance tracing)
Logcat Ferramenta nativa do Android para exibir logs do sistema e do app Uso simples via terminal (adb logcat); filtragem por tag ou nível

Análise de logs

Análise de logs é o processo de examinar os registros de eventos gerados por uma aplicação para identificar comportamentos anômalos, erros ou a origem de problemas em tempo real.

Monitoramento da comunicaçãoLogs registram detalhes da interação entre o app e as APIs de terceiros, facilitando a identificação de problemas.
Métricas de desempenhoPermitem acompanhar falhas, uso e eficiência da integração, ajudando a otimizar o sistema.
Rastreamento de errosCapturam falhas não identificadas por ferramentas automáticas, permitindo correções antes que afetem o usuário.

Tipos de logs

TipoO que registraExemplo
Logs de sistemaExecução geral do sistema operacional e do appConsumo de memória, erros de permissão
Logs personalizadosCriados pelo desenvolvedor para rastrear fluxos específicos Validação de tokens

Níveis de logs (Logcat)

NívelDescrição
Verbose (V)Mensagens detalhadas, úteis para depuração.
Debug (D)Informações úteis durante o desenvolvimento.
Info (I)Eventos gerais do sistema ou da aplicação.
Warning (W)Situações que podem gerar problemas.
Error (E) Mensagens de erro que interrompem um fluxo.
Situação — CarSmart (simulação de crise) A equipe da CarSmart enfrenta reclamações de usuários por falhas frequentes na sincronização com o Dropbox. A equipe também precisa sincronizar recibos com o Google Drive e monitorar falhas de autenticação (ex.: token expirado). Você é convocado(a) para liderar uma simulação de crise: analisar a situação, identificar a causa raiz e propor uma solução viável em 15 minutos, gerenciando também a comunicação com a equipe e os gestores.
Exemplos de log usados na aula: 
Log.e("CarSmartLog", "Erro: Token expirado durante autenticação")

val startTime = System.currentTimeMillis()
// Chamada à API
val endTime = System.currentTimeMillis()
