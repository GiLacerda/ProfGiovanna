Componentização e reutilização de interfaces

Onde revisar Unidade 3 · Componentes avançados de interface — Aula 1: Componentes personalizados

Um componente de interface encapsula um pedaço de lógica e layout, formando um bloco reutilizável — de um botão simples a estruturas mais complexas, como carrosséis e cards. Quanto melhor projetado, mais fácil é usar o mesmo componente em telas diferentes sem reescrever código.

Três princípios de um componente reutilizável

  • Encapsulamento — isola a lógica interna, tornando o componente independente do contexto onde é usado.
  • Modularidade — realiza uma função específica, sem depender excessivamente de coisas externas.
  • Reusabilidade — permite personalizações (via parâmetros) sem precisar alterar o código-base.

Boas práticas

  • Componentização modular — dividir a interface em partes menores que se combinam. Ex.: um ProductCard pode ser dividido em ProductImage, ProductTitle e ProductPrice.
  • Parâmetros e propriedades — permitem configurar o comportamento e os dados de cada instância do componente sem mudar seu código (ex.: título, preço, ação do botão).
  • Abstração de estilos com temas — um tema global de cores e fontes permite adaptar a aparência (ex.: modo claro/escuro) sem alterar a lógica do componente.
  • Composição em vez de herança — ao montar componentes complexos, compor a partir de subcomponentes reduz o acoplamento e mantém a modularidade.
Por que isso importa A reutilização acelera o desenvolvimento e garante que uma atualização no componente central se propague automaticamente para todas as instâncias — mantendo a consistência visual e de comportamento em todo o aplicativo.
Para discutir em sala Que componentes reutilizáveis vocês reconhecem em aplicativos que usam no dia a dia (cards, barras de navegação, botões de ação)?
2

Acessibilidade e usabilidade

Onde revisar Unidade 3 · Acessibilidade e usabilidade — Aulas 1 e 2: Princípios de acessibilidade / Testes de usabilidade

Os dois conceitos andam juntos, mas têm focos diferentes: acessibilidade garante que o aplicativo possa ser usado por pessoas com diferentes tipos de deficiência (visual, auditiva, motora, cognitiva); usabilidade garante que a experiência seja intuitiva, eficiente e agradável para qualquer usuário.

Planejamento de testes, passo a passo

  • 1. Definição de objetivos — conformidade com as diretrizes WCAG (Web Content Accessibility Guidelines) para acessibilidade; navegação intuitiva e eficiente para usabilidade.
  • 2. Identificação do público-alvo — considerar usuários com diferentes deficiências, faixas etárias e níveis de familiaridade com tecnologia.
  • 3. Seleção de ferramentas — leitores de tela como VoiceOver (iOS) e TalkBack (Android) para acessibilidade; softwares como Hotjar e UserTesting para usabilidade.
  • 4. Definição de métricas — taxa de conformidade com o WCAG e número de erros identificados por ferramentas automatizadas (acessibilidade); tempo para completar tarefas, número de cliques, taxa de erro e satisfação do usuário (usabilidade).

Na execução

  • Testes de acessibilidade verificam descrições para leitores de tela (atributo alt), navegação por teclado e contraste de cores.
  • Testes de usabilidade envolvem observar usuários reais navegando e usar mapas de calor (heatmaps) para ver onde eles clicam e onde encontram dificuldades.
  • Na análise, os problemas são classificados por severidade (crítico, médio, baixo) e reunidos num relatório com soluções recomendadas e impacto estimado.

Banco de dados relacional x NoSQL

Onde revisar Unidade 2 · Banco de dados avançados — Aula 1: Banco de dados relacional vs. NoSQL

A escolha do tipo de banco de dados impacta diretamente o desempenho e a escalabilidade de um aplicativo — não existe um "melhor" banco, e sim o mais adequado para cada cenário.

  • Bancos relacionais — organizam os dados em tabelas com relações bem definidas entre elas, priorizando consistência e integridade. São a escolha natural quando os dados têm uma estrutura fixa e as relações entre eles importam (ex.: cadastros, transações).
  • Bancos NoSQL — pensados para lidar com grandes volumes de dados heterogêneos, priorizando escalabilidade e flexibilidade. Facilitam o processamento de dados que mudam de formato ou crescem rapidamente (ex.: feeds, mensagens, catálogos variáveis).
Como pensar na escolha Pergunte: os dados têm uma estrutura fixa e relações importantes entre si, com necessidade forte de consistência? Tende a pedir um banco relacional. O volume de dados é grande, variável, e a prioridade é escalar rápido? Tende a pedir um NoSQL.
Para discutir em sala Peça exemplos de apps do celular dos alunos e discutam juntos: esse app provavelmente usa um banco relacional ou NoSQL — e por quê?

Fundamentos de UX (experiência do usuário)

Onde revisar Unidade 3 · Design e experiência do usuário (UX) — Aula 1: Fundamentos de UX

O design centrado no usuário (User-Centered Design — UCD) é uma abordagem que coloca as necessidades e preferências de quem vai usar o aplicativo no centro de todo o processo de desenvolvimento, prevenindo interfaces confusas e funcionalidades pouco intuitivas.

Quatro princípios fundamentais

  • Empatia com o usuário — compreender necessidades, limitações e o contexto emocional de quem usa o app (ex.: criar personas, como um idoso que precisa de botões maiores).
  • Participação ativa dos usuários — envolver o público desde a concepção até os testes finais, não só no final.
  • Interação contínua — melhorar com base em testes e feedback constantes, em vez de tratar o design como algo "pronto" de uma vez.
  • Acessibilidade universal — seguir diretrizes como o WCAG para garantir que qualquer pessoa consiga usar o produto.

Métodos de pesquisa com usuários

  • Entrevistas — exploram motivações, dificuldades e expectativas.
  • Testes de usabilidade — observam o usuário interagindo com o app para identificar problemas.
  • Mapas de calor — mostram as áreas mais acessadas da tela.
  • Questionários — coletam feedback quantitativo sobre satisfação.
  • Análise de concorrência — compara aplicativos parecidos para identificar boas práticas.

Prototipagem e wireframes

Onde revisar Unidade 3 · Design e experiência do usuário (UX) — Aula 2: Prototipagem e wireframes

Antes de programar uma tela, faz sentido primeiro estruturá-la e testar seu fluxo de navegação — é para isso que servem wireframes e protótipos.

  • Wireframe — organiza os elementos da interface de forma funcional, sem se preocupar com o visual final (cores, fontes, imagens). O foco é a estrutura e a disposição dos elementos na tela.
  • Protótipo — vai além do wireframe ao simular a interação do usuário com a interface, podendo ser navegável entre telas para representar o fluxo real de uso.
A diferença central O wireframe é estrutural e estático; o protótipo simula a interação e a navegação real entre as telas. Ferramentas como Figma e Adobe XD permitem criar os dois — mas não eliminam a necessidade de testar a interface, nem geram o código final automaticamente.
