Listagem e Cadastro com PHP + PDO — “Cadastro de Usuários”

Material de consulta com o código completo usado em aula: uma tela que lista usuários cadastrados no banco de dados e um formulário para cadastrar novos. Abaixo, cada arquivo é explicado parte por parte — a ideia é que vocês consigam voltar aqui sempre que precisarem relembrar a lógica.

1) Visão geral do exemplo

O tema deste exemplo é um cadastro de usuários (inspirado no jogo Candy Crush, só para deixar mais divertido): cada usuário tem um nome de login, um apelido (nickname) e uma cor favorita. A aplicação tem duas telas:

  • Listagem (index.php): mostra todos os usuários cadastrados em uma tabela.
  • Cadastro (cadastro.php): formulário que insere um novo usuário no banco.

A lógica geral é sempre a mesma nesse tipo de aplicação: PHP conecta ao banco, busca ou grava dados, e o HTML mostra o resultado na tela. O PHP não desenha nada visualmente — ele só gera o texto HTML que o navegador depois interpreta.

2) Estrutura de arquivos

ArquivoFunção
conn.php Abre a conexão com o banco de dados usando PDO. Todo arquivo que precisa falar com o banco começa incluindo este arquivo.
index.php Página principal. Busca todos os usuários no banco e monta a tabela HTML com os resultados.
cadastro.php Mostra o formulário de cadastro e, quando o formulário é enviado, insere o novo usuário no banco.
style.css Estilização visual: cores, espaçamento, aparência da tabela, do formulário e dos botões.

Note que não existe um arquivo separado só para "processar o cadastro": o próprio cadastro.php mostra o formulário e trata o envio dele, dependendo do método da requisição (GET ou POST). Essa é uma variação comum do padrão que vocês já viram.

3) conn.php — conexão com o banco

conn.php 
<?php

$host    = 'localhost';        // onde o banco está rodando
$dbname  = 'modular_pwiii';    // nome do banco
$usuario = 'root';
$senha   = '';

$dsn = "mysql:host=$host;dbname=$dbname;charset=utf8mb4";

try {
    $pdo = new PDO($dsn, $usuario, $senha);
    //echo "Conectado com sucesso!";
} catch (PDOException $e) {
    die("Erro ao conectar: " . $e->getMessage());
}

O que cada parte faz:

  • $host, $dbname, $usuario, $senha: são as informações necessárias para acessar o banco MySQL — endereço do servidor, nome do banco e credenciais de acesso.
  • $dsn (Data Source Name): é uma "receita" que diz ao PHP qual driver usar (mysql), em qual host e banco conectar, e qual codificação de caracteres usar (utf8mb4, que suporta acentos e emojis).
  • new PDO(...): PDO (PHP Data Objects) é a classe do PHP usada para se conectar a bancos de dados de forma segura e padronizada. Se a conexão der certo, o objeto é guardado na variável $pdo — é esse objeto que vamos reaproveitar em index.php e cadastro.php.
  • try { ... } catch (PDOException $e) { ... }: se a conexão falhar (senha errada, banco fora do ar etc.), o PHP lança uma exceção. O bloco catch "pega" esse erro e chama die(), que interrompe a execução mostrando a mensagem de erro, em vez de deixar a página quebrar silenciosamente.

Por que isolar isso em um arquivo próprio? Porque tanto index.php quanto cadastro.php precisam se conectar ao banco. Em vez de repetir esse código nos dois arquivos, cada um simplesmente faz require_once "conn.php"; no início.

4) index.php — listagem de usuários

index.php 
<?php
require_once "conn.php";

$stmt = $pdo->prepare("SELECT id, usuario, nickname, cor FROM usuario");
$stmt->execute();

$usuarios = $stmt->fetchAll(PDO::FETCH_ASSOC);
?>
<HTML>
    <HEAD>
        <META CHARSET="UTF-8"/>
        <LINK HREF="style.css" REL="STYLESHEET"/>
        <TITLE>Candy Crush</TITLE>
    </HEAD>
    <BODY>
        <H1>Lista de usuários</H1>
        <A HREF="cadastro.php" CLASS="btn-novo">Novo +</A>
        <TABLE>
            <TR>
                <TH>ID</TH>
                <TH>Usuário</TH>
                <TH>Nick</TH>
                <TH>Cor</TH>
            </TR>
            <?php
            foreach ($usuarios as $usuario) {
                echo "<TR>";
                echo "<TD>".$usuario['id']."</TD>";
                echo "<TD>".$usuario['usuario']."</TD>";
                echo "<TD>".$usuario['nickname']."</TD>";
                echo "<TD><span class='color-badge' style='background-color: ".$usuario['cor'].";'></span>".$usuario['cor']."</TD>";
                echo "</TR>";
            }
            ?>
        </TABLE>
    </BODY>
</HTML>

Passo a passo da lógica:

  1. require_once "conn.php"; — inclui o arquivo de conexão. Depois desta linha, a variável $pdo já existe e está pronta para uso. O _once garante que o arquivo não seja incluído duas vezes, evitando erro de "conexão já criada".
  2. $pdo->prepare("SELECT id, usuario, nickname, cor FROM usuario") — prepara uma consulta SQL que busca as quatro colunas da tabela usuario. "Preparar" significa que o PHP monta a consulta antes de executá-la (isso também é o que protege contra SQL Injection quando a consulta tem parâmetros — aqui não tem, mas é o mesmo mecanismo usado em cadastro.php).
  3. $stmt->execute(); — de fato executa a consulta no banco de dados.
  4. $stmt->fetchAll(PDO::FETCH_ASSOC) — pega todos os resultados de uma vez e guarda em $usuarios como um array de arrays associativos. Ou seja, cada usuário vira algo como ['id' => 1, 'usuario' => 'gio', 'nickname' => 'Gi', 'cor' => '#ff0000'].
  5. A partir da linha <HTML>, o arquivo passa a gerar a página que o navegador vai exibir. Repare que o <?php ... ?> "corta e volta" para o HTML puro sempre que for necessário.
  6. <A HREF="cadastro.php" CLASS="btn-novo">Novo +</A> — é o link/botão que leva o usuário até a tela de cadastro. É a ligação entre as duas telas.
  7. foreach ($usuarios as $usuario) { ... } — este é o coração da listagem: um laço que percorre cada usuário encontrado no banco e, para cada um, imprime (echo) uma linha <TR> da tabela com os dados daquele usuário.
  8. Dentro do laço, cada echo concatena texto HTML com os valores vindos do banco ($usuario['id'], $usuario['usuario'] etc.) usando o operador . (ponto), que em PHP serve para "colar" strings.
  9. A célula da cor é a mais interessante: ela cria uma <span> circular (class="color-badge", estilizada no CSS) cujo background-color é definido dinamicamente com o valor salvo no banco — por isso a "bolinha" aparece pintada com a cor exata que o usuário escolheu no cadastro.

5) cadastro.php — formulário e inserção

cadastro.php 
<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    require_once "conn.php";

    $sql = "INSERT INTO usuario (usuario, nickname, cor)
            VALUES (:usuario, :nickname, :cor)";

    $stmt = $pdo->prepare($sql);
    $stmt->execute($_POST);

    header("Location: ./index.php");
}
?>
<HTML>
    <HEAD>
        <META CHARSET="UTF-8"/>
        <LINK HREF="style.css" REL="STYLESHEET"/>
        <TITLE>Candy Crush</TITLE>
    </HEAD>
    <BODY>
        <H1>Cadastro de usuários</H1>
        <FORM ACTION="cadastro.php" METHOD="POST">
            <INPUT TYPE="TEXT" NAME="usuario" PLACEHOLDER="User" REQUIRED/><BR/>
            <INPUT TYPE="TEXT" NAME="nickname" PLACEHOLDER="Nick" REQUIRED/><BR/>
            <INPUT TYPE="COLOR" NAME="cor" PLACEHOLDER="Cor"/><BR/>
            <BUTTON TYPE="SUBMIT">Enviar</BUTTON>
        </FORM>
    </BODY>
</HTML>

Esse arquivo faz duas coisas diferentes, dependendo de como foi acessado:

  1. Quando alguém apenas abre a página (clicando em "Novo +" no index.php), o navegador faz uma requisição GET. Nesse caso, $_SERVER['REQUEST_METHOD'] é "GET", então o if não entra, e o PHP simplesmente mostra o formulário HTML.
  2. Quando o formulário é enviado (botão "Enviar" clicado), o navegador faz uma requisição POST para o próprio cadastro.php (veja ACTION="cadastro.php" no <FORM>). Agora $_SERVER['REQUEST_METHOD'] === 'POST' é verdadeiro, e o bloco dentro do if é executado antes de qualquer HTML ser mostrado.

Dentro do if, o que acontece:

  • require_once "conn.php"; — conecta ao banco (só precisa disso quando for realmente gravar algo).
  • $sql = "INSERT INTO usuario (...) VALUES (:usuario, :nickname, :cor)" — monta o comando SQL de inserção. Os :usuario, :nickname e :cor são parâmetros nomeados: espaços reservados que serão preenchidos depois, em vez de colar o texto direto na consulta. Isso é o que se chama de prepared statement (consulta preparada).
  • $stmt = $pdo->prepare($sql); — prepara essa consulta no banco.
  • $stmt->execute($_POST); — aqui está o "pulo do gato": o array $_POST (que contém tudo o que veio do formulário, como ['usuario' => 'gio', 'nickname' => 'Gi', 'cor' => '#ff0000']) é passado direto para o execute(). O PDO casa automaticamente as chaves do array (usuario, nickname, cor) com os parâmetros nomeados (:usuario, :nickname, :cor) da consulta, e insere os valores com segurança — isso evita SQL Injection, porque o PDO trata os valores como dados, nunca como comandos SQL.
  • header("Location: ./index.php"); — depois de inserir, redireciona o navegador de volta para a listagem. É por isso que, ao cadastrar um novo usuário, você "volta" automaticamente para a tabela e já vê o novo registro lá.

No formulário HTML:

  • NAME="usuario", NAME="nickname", NAME="cor" — o atributo NAME de cada <INPUT> é a chave que vai aparecer dentro de $_POST. Se o NAME não bater com o parâmetro nomeado da consulta (:usuario etc.), o cadastro não funciona.
  • REQUIRED — validação simples feita pelo próprio navegador: impede o envio se o campo estiver vazio (mas não substitui validação no servidor em um projeto real).
  • TYPE="COLOR" — cria um seletor de cor nativo do navegador; o valor enviado é sempre uma cor no formato hexadecimal, como #3498db.

6) style.css — o essencial da estilização

style.css (trechos) 
* {
    box-sizing: border-box;
    margin: 0;
    padding: 0;
}

form, table {
    background: #ffffff;
    padding: 25px;
    border-radius: 8px;
    box-shadow: 0 4px 10px rgba(0, 0, 0, 0.08);
}

.color-badge {
    display: inline-block;
    width: 18px;
    height: 18px;
    border-radius: 50%;
    border: 1px solid #ccc;
}

Pontos que valem destacar para quem está começando com CSS:

  • * { box-sizing: border-box; margin: 0; padding: 0; } — um "reset" básico: remove as margens e espaçamentos padrão que cada navegador aplica de forma diferente, e faz com que padding e border passem a contar dentro da largura/altura do elemento, o que facilita calcular tamanhos.
  • form, table { ... } — os seletores separados por vírgula recebem o mesmo estilo. Aqui, tanto o formulário quanto a tabela viram um "cartão" branco com cantos arredondados e uma sombra suave (box-shadow), dando aquele visual de card que aparece na tela.
  • .color-badge — a classe usada na "bolinha" colorida da tabela. border-radius: 50% transforma o quadrado em um círculo perfeito; a cor de fundo em si não vem do CSS — ela é definida linha a linha pelo PHP, direto no atributo style de cada <span> (volte na explicação do index.php para relembrar).
  • O restante do arquivo segue o mesmo princípio: classes reutilizáveis (.btn-novo para o botão verde, seletores como tr:hover para destacar a linha ao passar o mouse, th para o cabeçalho azul da tabela) — nada além do que já foi visto em aulas anteriores de CSS.

8) Glossário rápido

TermoO que é
PDO PHP Data Objects — classe do PHP para conectar e conversar com bancos de dados de forma padronizada, independente do banco usado (MySQL, PostgreSQL, SQLite...).
Prepared statement (consulta preparada) Uma consulta SQL montada com espaços reservados (:nome ou ?) que são preenchidos depois com valores. Protege contra SQL Injection.
$_POST Array superglobal do PHP que contém os dados enviados por um formulário com METHOD="POST", usando o NAME de cada campo como chave.
$_SERVER['REQUEST_METHOD'] Informa qual método HTTP foi usado na requisição atual: normalmente "GET" (abrir uma página) ou "POST" (enviar um formulário).
header("Location: ...") Instrução que manda o navegador redirecionar para outra página. Precisa ser chamada antes de qualquer HTML ser enviado, por isso fica no topo do arquivo, dentro do if.
require_once Inclui o conteúdo de outro arquivo PHP no ponto onde é chamado, garantindo que aquele arquivo não seja incluído mais de uma vez na mesma execução.

9) Dicas e cuidados (para ir além deste exemplo)

  • Este exemplo usa echo para montar HTML direto com os dados do banco. Em um projeto real, vale usar htmlspecialchars() ao imprimir dados do usuário na tela, para evitar problemas se alguém cadastrar um valor com caracteres especiais de HTML.
  • Os nomes das tags aqui estão em maiúsculo (<HTML>, <BODY>...) — o navegador aceita normalmente, mas o padrão mais usado atualmente é escrever tags HTML em minúsculo.
  • Se a tela de listagem aparecer em branco ou der erro de conexão, confira primeiro o conn.php: nome do banco ($dbname), usuário e senha são as causas mais comuns de erro.
  • Para testar sozinho: crie a tabela usuario no banco modular_pwiii com as colunas id (chave primária, auto incremento), usuario, nickname e cor, depois rode este projeto em um servidor local com PHP e MySQL (por exemplo, XAMPP ou php -S localhost:8000 com o MySQL rodando à parte).
