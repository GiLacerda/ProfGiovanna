🎓 Melhores Práticas de Programação

Princípios fundamentais aplicáveis a todas as linguagens

🚀 Por Que Boas Práticas Importam?

Código bem estruturado não é luxo - é essencial para:

  • Facilitar manutenção e correção de bugs
  • Permitir que outros entendam seu código
  • Reduzir tempo de desenvolvimento futuro
  • Evitar erros e comportamentos inesperados
  • Profissionalizar seu trabalho
💡 Lembre-se: Você escreve código uma vez, mas o lê dezenas de vezes. Também outras pessoas lerão seu código.

📝 1. Estilo de Codificação

Estilo de codificação define as convenções visuais e estruturais do seu código. Consistência é a chave.

Princípios Fundamentais

  • Mantenha consistência em todo o projeto
  • Use nomes significativos e descritivos
  • Siga convenções da comunidade/linguagem
  • Escolha um padrão e mantenha-o

1.1 Nomenclatura de Variáveis

❌ Nomes Ruins

x = 10 y = x + 5 temp = calcular(y) resultado = temp * 2 def f(a): return a * 2 usuarios = [u1, u2, u3]

✅ Nomes Bons

idade_usuario = 10 idade_ajustada = idade_usuario + 5 imposto_calculado = calcular_imposto(idade_ajustada) salario_final = imposto_calculado * 2 def duplicar_valor(numero): return numero * 2 lista_usuarios = [usuario1, usuario2, usuario3]

1.2 Convenções de Nomenclatura

Elemento Convenção Exemplo Linguagens
Variáveis snake_case ou camelCase nome_usuario ou nomeUsuario Python, Java, JavaScript
Constantes UPPER_SNAKE_CASE MAX_TENTATIVAS, PI_VALOR Todas
Funções/Métodos snake_case ou camelCase calcular_imposto() ou calcularImposto() Python, Java, JavaScript
Classes PascalCase UsuarioPremium, CalculadoraImposto Java, Python, C#

1.3 Regras de Nomenclatura

  • Seja descritivo: Use nomes que expliquem o propósito
  • Evite abreviações: "usr" vs "usuario" - prefira clareza
  • Use inglês ou português consistentemente: não misture
  • Nomes positivos: "ativo" melhor que "nao_inativo"
  • Para booleanos: Use prefixos "é", "tem", "pode"
Exemplo: Nomenclatura de Booleanos
# Bom usuario_ativo = True tem_permissao = False pode_deletar = True eh_premium = False # Ruim status = True permissao = False deletar = True premium = False

1.4 Comprimento de Identificadores

Diretriz:
  • Variáveis locais: 1-3 palavras (ok: x, contador, tempo_espera)
  • Variáveis globais: 2-4 palavras (necessário ser descritivo)
  • Funções/Métodos: verbo + objeto (ex: calcular_imposto, enviar_email)

📐 2. Indentação

Indentação apropriada torna visível a hierarquia e estrutura do código. Sem ela, código é ilegível.

Regras Básicas

  • Use 2, 3 ou 4 espaços ou TAB (NUNCA misture tabs e espaços, PADRONIZE)
  • Um nível de indentação = um nível de hierarquia
  • Seja consistente em todo o projeto

2.1 Indentação em Estruturas de Controle

❌ Sem Indentação

def processar_usuarios(usuarios): if usuarios is not None: for usuario in usuarios: if usuario.ativo: resultado = calcular(usuario) salvar(resultado) print("Pronto") return True

✅ Com Indentação

def processar_usuarios(usuarios): if usuarios is not None: for usuario in usuarios: if usuario.ativo: resultado = calcular(usuario) salvar(resultado) print("Pronto") return True

2.2 Indentação em Múltiplas Linhas

Para Linhas Longas
# Ruim - linha muito longa resultado = funcao_complexa(parametro1, parametro2, parametro3, parametro4, parametro5) # Bom - dividido em linhas resultado = funcao_complexa( parametro1, parametro2, parametro3, parametro4, parametro5 ) # Bom - com alinhamento dados = { "nome": "João", "idade": 30, "email": "joao@email.com" }

2.3 Espaço em Branco Estratégico

  • Deixe linha em branco entre funções/métodos
  • Deixe linha em branco entre grupos lógicos de código
  • NÃO deixe linhas em branco desnecessárias no meio de lógica
def calcular_imposto(salario): taxa = 0.15 imposto = salario * taxa return imposto def aplicar_desconto(preco, percentual): desconto = preco * (percentual / 100) preco_final = preco - desconto return preco_final

👁️ 3. Legibilidade

Código legível é código que qualquer pessoa pode entender rapidamente.

3.1 Simplicidade Primeiro

❌ Complexo e Confuso

resultado = [x**2 for x in lista if x%2==0] def f(a,b,c):return a+b if c else a-b valor = x if x>0 else (0 if x<-10 else -x)

✅ Claro e Direto

numeros_pares_quadrados = [] for numero in lista: if numero % 2 == 0: quadrado = numero ** 2 numeros_pares_quadrados.append(quadrado) def calcular_resultado(a, b, usar_soma): if usar_soma: return a + b else: return a - b if valor > 0: valor_final = valor elif valor < -10: valor_final = 0 else: valor_final = -valor
⚠️ Regra de Ouro: "Código escrito visando a brevidade raramente é escrito visando a clareza."

3.2 Uma Responsabilidade por Função

❌ Múltiplas Responsabilidades

def processar_pedido(pedido): # Validar, calcular, salvar, enviar email # Tudo em uma função! if not validar_pedido(pedido): return False total = 0 for item in pedido['itens']: total += item['preco'] * item['qtd'] pedido['total'] = total salvar_banco_dados(pedido) enviar_email_confirmacao(pedido) retornar True

✅ Uma Responsabilidade

def validar_pedido(pedido): return len(pedido['itens']) > 0 def calcular_total(pedido): total = 0 for item in pedido['itens']: total += item['preco'] * item['qtd'] return total def processar_pedido(pedido): if not validar_pedido(pedido): return False pedido['total'] = calcular_total(pedido) salvar_banco_dados(pedido) enviar_email_confirmacao(pedido) return True

3.3 Limite de Comprimento de Linhas

Recomendação: Mantenha linhas com até 80-100 caracteres

Por quê?
  • Facilita leitura em telas pequenas
  • Permite abrir dois arquivos lado a lado
  • Reduz scroll horizontal
  • Melhor para revisão de código

3.4 Evite Números Mágicos

❌ Números Mágicos

if idade >= 18: pode_votar = True desconto = preco * 0.15 if tentativas > 3: bloquear_conta()

✅ Constantes Nomeadas

IDADE_MINIMA_VOTO = 18 TAXA_DESCONTO = 0.15 TENTATIVAS_MAXIMAS = 3 if idade >= IDADE_MINIMA_VOTO: pode_votar = True desconto = preco * TAXA_DESCONTO if tentativas > TENTATIVAS_MAXIMAS: bloquear_conta()

3.5 Funções Pequenas e Focadas

  • Funções devem fazer uma coisa bem
  • Tamanho ideal: 10-30 linhas
  • Se precisa de "E TAMBÉM" na descrição, divida a função

💬 4. Comentários

Comentários explicam o "por quê", não o "o quê". O código mostra o que faz.

Tipos de Comentários

A. Comentários de Seção

Separar blocos principais de código
# ==================== VALIDAÇÃO ==================== def validar_email(email): return '@' in email and '.' in email # ==================== PROCESSAMENTO ==================== def processar_dados(dados): if validar_email(dados['email']): salvar(dados) # ==================== RELATÓRIOS ==================== def gerar_relatorio(): pass

B. Comentários Explicativos

Explicar a lógica ou razão
# Usar set para remover duplicatas eficientemente # (O(n) em vez de O(n²) com lista aninhada) ids_unicos = set(lista_ids) # Multiplicar por 100 para converter para porcentagem taxa_exibicao = (cliques / impressoes) * 100 # Aguardar antes de tentar reconectar # para evitar sobrecarregar o servidor time.sleep(30) tentar_reconectar()

C. Comentários de TODO e FIXME

Marcar trabalho futuro
# TODO: Adicionar validação de CPF def registrar_usuario(cpf): salvar_banco_dados(cpf) # FIXME: Este código é lento com arquivos > 1GB def carregar_arquivo(caminho): with open(caminho) as f: return f.read() # HACK: Solução temporária até refatorar banco de dados usuario = banco.query("SELECT * FROM usuarios")[0]

D. Documentação de Funções

Docstring (Documentação Estruturada)
def calcular_idade(data_nascimento): """ Calcula a idade de uma pessoa baseado na data de nascimento. Args: data_nascimento (datetime): Data de nascimento da pessoa Returns: int: Idade em anos Raises: ValueError: Se data é no futuro """ hoje = datetime.now().date() if data_nascimento > hoje: raise ValueError("Data não pode ser no futuro") idade = hoje.year - data_nascimento.year return idade

Boas Práticas de Comentários

  • Seja breve: Comentários devem ser concisos
  • Explique o "por quê": Não repita o código
  • Atualize comentários: Código desatualizado é pior que sem comentário
  • Use primeira pessoa: "Calculamos o imposto" é melhor que "O imposto é calculado"
  • Evite óbvio: Não comente "i = i + 1"
  • Marque problemas: Use TODO, FIXME, HACK, NOTE

Comparação: Bom vs Ruim

❌ Comentários Ruins

# Incrementa x x = x + 1 # Loop pelos usuários for usuario in usuarios: # Imprime o usuário print(usuario)

✅ Comentários Bons

# Contador começa em 1, não zero contador = contador + 1 # Verificar cada usuário para permissões for usuario in usuarios: # Apenas log de diagnóstico em modo debug if DEBUG: print(usuario)

📚 6. Exemplo Completo

Veja como aplicar todas as práticas juntas:

Antes (Sem Boas Práticas)

def p(l): r=[] for i in l: if i%2==0: r.append(i*i) return r x=p([1,2,3,4,5]) print(x) def c(n): s=0 for i in range(1,n): if n%i==0: s+=i return s==n

Depois (Com Boas Práticas)

# ==================== UTILITÁRIOS MATEMÁTICOS ==================== def extrair_pares_quadrados(numeros): """ Extrai números pares e retorna seus quadrados. Args: numeros (list): Lista de inteiros Returns: list: Quadrados dos números pares """ resultado = [] for numero in numeros: if numero % 2 == 0: quadrado = numero ** 2 resultado.append(quadrado) return resultado def eh_numero_perfeito(numero): """ Verifica se um número é perfeito. Um número perfeito é igual à soma de seus divisores. Exemplo: 6 = 1 + 2 + 3 Args: numero (int): Número a verificar Returns: bool: True se é número perfeito """ soma_divisores = 0 for divisor in range(1, numero): if numero % divisor == 0: soma_divisores += divisor return soma_divisores == numero # ==================== EXECUÇÃO ==================== if __name__ == "__main__": numeros = [1, 2, 3, 4, 5] pares_quadrados = extrair_pares_quadrados(numeros) print(f"Pares quadrados: {pares_quadrados}") eh_perfeito = eh_numero_perfeito(6) print(f"6 é número perfeito: {eh_perfeito}")
Melhorias Aplicadas:
  • ✓ Nomes descritivos (p → extrair_pares_quadrados)
  • ✓ Variáveis significativas (r → resultado, l → numeros)
  • ✓ Indentação consistente
  • ✓ Funções pequenas e focadas
  • ✓ Documentação clara (docstrings)
  • ✓ Comentários de seção
  • ✓ Sem números mágicos
  • ✓ Espaço em branco estratégico
